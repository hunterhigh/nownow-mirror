# 观复主开发方案 v1

状态：**用户已批准按本方案执行；仍不授权部署、迁移或推送。**

制定日期：2026-09-06（Asia/Shanghai）

## 1. 方案结论

首个可用版本以一个人的长期工作为中心：快速进入日／周／月工作文档，在连续正文中记录、形成行动、安排、完成、回看，并把非目标类信息放入独立的「元」。现有 `@`、成员查看和块级隐私继续保留，但首版不增加负责人、评论、多人实时编辑等团队能力。

选择这一路径的依据：

- 用户已确认产品主体是工作文档，任务只是其中一种语义内容，而不是独立卡片系统（`docs/product-brief.md:18`、`docs/product-brief.md:36-38`）。
- 日／周／月属于文档顶部的时间视图；侧栏最终只保留工作区、元、共作（`docs/product-brief.md:24-35`）。
- 现有实现已经拥有 Tiptap 文档、保存保护、版本前置条件、公开投影与 `@` 索引，适合渐进式改造，不适合推倒重写（`src/components/DocEditor.jsx:102-106`、`src/lib/docsApi.js:55-119`、`src/lib/resilientDocs.js:267-345`）。
- 用户已同意个人版优先、团队增强后置；这一结论取代旧的待确认假设。

## 2. 首版范围

### 2.1 必须完成

1. **顺滑工作文档**：所见即所得 Markdown、Slash、剪贴板、导入／导出、中文输入法、长文与撤销可靠；发布门槛继续以编辑器契约为准（`docs/editor-contract.md:94-149`）。
2. **日／周／月闭环**：进入即写；周期切换、过去记录、跨日承接与回顾不要求先创建页面。现有入口和周期状态位于 `src/Board.jsx:184-219`，现有时间线位于 `src/components/DocTimeline.jsx`。
3. **具名工作文档**：Markdown 默认新建文档；普通新建、重命名、归档、搜索和打开均可用。当前导入暂借 `doc_tag` 作为具名槽（`src/lib/markdownImport.js:17-40`），发布前必须替换或正式确认长期模型。
4. **元**：侧栏独立入口，不出现日／周／月，不进入目标型任务聚合；支持写作、搜索、导入和导出（`docs/design.md:218-229`）。
5. **个人行动视图**：任务仍以文档中的 `taskItem` 为真源；系统派生「待安排、今日、以后、已完成」索引，并可跳回原文，不让任务脱离上下文（`docs/product-brief.md:118-136`）。
6. **观复视觉系统**：明体／宋体长文、少量碑帖层级、纯色东方主题、背景与印章固定映射、纤细桌面构图；不做纸张纹理（`docs/product-brief.md:19-33`、`docs/design.md:174-184`、`docs/design.md:238-247`）。
7. **数据可信**：离线草稿、失败重试、冲突前置条件、历史版本、私密块、完整导出和可恢复性不得退化（`AGENTS.md:16-19`、`src/lib/resilientDocs.js:56-73`）。
8. **私有试用条件**：独立开发环境、迁移演练、权限矩阵、备份／恢复、浏览器矩阵与用户体验验收全部通过（`.omx/plans/development-workflow.md:49-63`）。

### 2.2 首版明确不做

- 不做 Notion 式数据库、看板、公式和无限嵌套页面。
- 不做 Obsidian 插件生态、关系图谱或本地文件夹同步。
- 不做任务独立页面、复杂优先级、重复任务、日历双向同步和 AI 自动安排。
- 不增加团队负责人、块评论、在线状态、多人实时编辑或组织管理。
- 不做纸张纹理、Logo 自由选色、通用图标式日／周／月导航。
- 不公开仓库、不更改远程、不部署到原项目环境；这些边界来自 `AGENTS.md:21-27`。

## 3. 首版核心用户闭环

```text
打开观复
  → 默认进入今天的工作文档
  → 自然输入／Markdown／Slash 记录
  → 将正文中的 taskItem 形成行动
  → 在行动视图安排到今天或以后
  → 从行动跳回原文继续工作
  → 周／月回看并承接未完成内容
  → 非目标信息进入「元」
  → 随时搜索、导出、离线恢复或查看历史版本
```

首版是否成功，不以“页面数量”判断，而以以下完整任务验证：一个新用户能在不阅读说明的情况下，于 10 分钟内完成记录、创建行动、安排、完成、回到上下文、进入元、搜索和导出；全程没有数据丢失、强制弹窗或必须使用鼠标的步骤。

## 4. 架构原则

1. **文档是真源**：`doc_json` 继续保存语义内容；Markdown 是输入输出协议，任务表与搜索表只做可重建索引（`AGENTS.md:16`、`docs/editor-contract.md:64-69`）。
2. **任务不复制正文**：任务状态、文字和上下文来自具有稳定 ID 的 `taskItem`；派生索引丢失时可从文档重建。
3. **UI 与数据分层**：组件只发领域动作；数据库访问留在 `src/lib/`，延续 `DocEditor → DocBlock → resilientDocs → docsApi` 的现有边界（`src/components/DocBlock.jsx:27-103`）。
4. **迁移只增量**：不改写历史 migration；先在隔离库演练，再决定是否执行新 migration（`AGENTS.md:25-27`）。
5. **可靠性高于装饰**：任何视觉改造不得破坏选区、IME、Undo、草稿、公开投影和权限（`AGENTS.md:31-34`）。
6. **个人优先但不破坏协作**：首版不扩展协作，现有 `@` 与成员读取必须继续回归；`@` 不等于个人任务（`AGENTS.md:18-19`）。

## 7. 十二个开发切片

### S0｜稳定开发基线

目标：把当前探索成果变成可继续迭代的清晰起点。

交付：

- 审阅并整理当前 `codex/workstation-init` 未提交差异，分离初始化、编辑器、文档和测试变更；未经授权不提交或推送。
- 创建 `docs/backlog.md`，只录入已确认的 S0–S11，不把候选池自动转为需求。
- 更新 `docs/baseline.md` 的当前测试数、lint、构建体积和已修改模块；旧基线保留日期语义。
- 固定受支持 Node 版本；当前 Node `24.13.0` 不满足已记录的 jsdom 最低小版本（`docs/baseline.md:40-53`）。
- 持续记录磁盘安全余量；此前仅余约 1.7 GiB 并触发过 `ENOSPC`。用户已明确要求不再清理其他缓存并继续开发，因此低空间只保留警告；只有实际出现 `ENOSPC` 时才停止当前命令并报告。

验收：`npm ci`、`npm test`、`npm run lint`、`npm run build`、`git diff --check` 全部可重复；测试基线不少于当前 8 文件／71 测试；lint 不高于当前 2 个既有 warning；磁盘与 Node 版本记录在基线；低空间风险经用户接受，不再作为预防性阻断条件。

### S1｜编辑器 P0 封板

目标：完整满足 `docs/editor-contract.md`，然后冻结文档 schema 进入上层功能开发。

交付：

- 每个 Slash 项分别验证节点类型、触发文本删除、焦点与一次 Undo；Slash 定义从 `DocEditor.jsx:131-153` 提取为可测试注册表。
- 补齐嵌套列表、嵌套任务、表格编辑、代码语言、链接末尾输入、HTML／Markdown／纯文本／图片粘贴四路浏览器测试。
- 真人执行 macOS 拼音、双拼、五笔测试：组合输入中不弹 Slash／成员菜单、不触发 Markdown 转换，结束后不丢字、不重字、不跳光标（`docs/editor-contract.md:122-128`）。
- 在正式登录应用而非仅 harness 中验证导入新建、追加、刷新、离线恢复、导出再导入。
- 校验私密 Callout、私密任务、成员 mention、日期戳与颜色的完整导出及公开导出差异。

验收：契约 `docs/editor-contract.md:130-149` 全部勾选；5 万字／200 块输入 p95 单次主线程处理低于 50ms；保存防抖保持 600ms 且连续输入不产生每键网络请求；真实 IME 检查表由用户或指定测试者签字。

### S2｜个人工作信息架构定稿

目标：在改数据库前，把“一个人一天如何工作”落成低保真可走通路径。

交付：

- 桌面壳只保留：工作区（文档、行动、与我相关）、元、共作；不恢复最近／项目（`docs/design.md:218-223`）。
- 文档顶部统一日／周／月、当前文档名、显示；不出现“插入”主入口（`docs/design.md:231-236`）。
- 定义具名文档列表、元、行动视图、搜索、设置的空／加载／错误／离线状态。
- 定义行动最小状态：待安排、今日、以后、已完成；优先级、截止日期、重复规则不进入首版。
- 输出键盘路径与焦点图：`⌘K` 搜索、`/` 内容命令、Esc 返回、上下选择、Enter 确认。

验收：在 1440、1024、768、390px 原型中完成核心用户闭环；无横向溢出；所有操作可不用鼠标完成；用户确认信息层级后才能进入 S5/S8。

### S3｜隔离环境与数据模型 ADR

目标：建立不会触碰原项目数据的开发环境，并确定具名文档、元和任务索引的长期模型。

推荐决策：增量扩展现有 `docs`，而不是复制一张新的内容表。

- 为 `docs` 增加 `doc_kind`（`periodic | named | yuan`）、可空 `title`、归档和排序元数据；保留 `doc_json`／public 投影与 `id`。
- 周期文档继续使用现有 `(owner, section, period_key, tag_id)` 约束；具名文档按 `id` 读写，`doc_tags` 回归分类属性，不再承担文档身份。当前约束见 `supabase/migration-022-doc-tags.sql:44-53`。
- 为 taskItem 增加稳定 `task_id`；新增 `doc_tasks` 仅存可重建索引，不成为正文真源。
- `yuan` 默认排除在行动索引之外；如以后需要显式纳入，以用户动作决定。

交付：`docs/data-model.md`、权限矩阵、增量 migration 草案、迁移前检查、回滚 SQL、空库和旧库两条演练记录。

验收：仅在用户授权的隔离 Supabase 中执行；旧周期文档数量和内容哈希迁移前后相同；owner 可读写全文；非 owner 只能按现有公开投影读取；版本历史全文仍 owner-only（`supabase/migration-020-doc-privacy.sql:51-59`）；回滚演练可恢复到迁移前 schema 与数据快照。

### S4｜观复视觉基础

目标：先建 token 与组件规则，再替换正式应用外观。

交付：

- 两套正文家族：明体、宋体；所有字体本地托管并记录许可证、字重、中文覆盖和失败回退。
- 碑帖／印章字体只用于「观复」、题签或空态短句，不承担正文。
- 至少 8 套、最多 12 套纯色主题；每套固定 `page/surface/ink/muted/line/accent/seal-bg/seal-fg`，不存在 Logo 色独立控件。
- 印章固定映射满足：白／月白配朱红，蓝灰配黛蓝，消炭配米白（`docs/design.md:238-247`）。
- 组件基线：文字导航、无图标时间入口、按钮、菜单、对话框、任务勾选、Callout、输入选区和错误提示。

验收：每套主题正文／控件对比度至少 4.5:1；200% 缩放可用；明体／宋体切换不引发布局抖动；刷新后主题保持；逐主题截图证明 seal token 固定且设置中无 Logo 色控件。

### S5｜工作区壳与周期文档

目标：将正式 `Board` 收敛为观复桌面结构，不改动文档保存语义。

交付：

- 渐进提取应用壳、侧栏和顶部工具栏，保留 `Board` 的认证、搜索和成员逻辑。
- 顶部使用「日／周／月」单字入口；元只在侧栏；收集箱语义根据 S2 结果并入“待安排”或明确保留，不再使用不符合哲学的通用图标。
- 桌面基准：侧栏约 220px，文档模块最大 940px，正文约 780px（`docs/design.md:174-178`）。
- 保留当前周期、过去周期、跨日承接与只读成员页能力。

验收：1440 与 1024 保持完整桌面布局；560 以下进入移动布局；切换周期不丢未保存草稿、不重置选区；现有成员页和通知跳转回归通过。

### S6｜具名文档与元

目标：使“新建文档”和“元”成为真实长期数据能力。

交付：

- 将 `src/lib/markdownImport.js:17-40` 从 `doc_tag` 兼容层切换到按文档 ID 创建。
- 具名文档支持新建、命名、重命名、归档、恢复、搜索、Markdown 导入／导出。
- 元使用独立 `doc_kind=yuan`，隐藏日／周／月和行动型提示；仍复用同一编辑器、草稿和版本能力。
- 文档删除默认归档；永久删除不进入首版 UI。

验收：重名、空名、超长名、离线创建、创建失败、归档恢复均有测试；导入新建不改变当前文档；元内容不出现在行动视图，但可被搜索和完整导出；刷新和重新登录后导航位置正确。

### S7｜任务语义与派生索引

目标：让文档中的行动可稳定检索，而不创建第二份内容真源。

交付：

- 每个 taskItem 拥有不可重复的 `task_id`；复制／导入生成新 ID，移动保留 ID，重复粘贴不覆盖原任务。
- `doc_tasks` 派生字段仅包含：task_id、doc_id、owner、checked、纯文本、来源位置、周期／计划日期、更新时间和可见性投影。
- 文档成功保存后幂等同步索引；索引失败不阻断正文保存，并进入可观察的待重建状态。
- 提供按文档和按账号重建索引的管理路径；不读取私密任务给其他成员。

验收：随机生成 1,000 个任务做保存／重建，任务数量、ID、状态和源文档完全一致；删除、复制、移动、撤销、离线重放后无重复索引；私密任务跨账号查询为 0 行。

### S8｜个人行动闭环

目标：从文档形成可执行的个人安排，但文档仍是主界面。

交付：

- 工作区内提供轻量行动视图：待安排、今日、以后、已完成。
- 每项只显示任务文字、来源文档和必要日期；点击跳回原文并定位任务。
- 支持完成／撤销、安排到今天／以后、移回待安排；所有动作反写原 taskItem。
- 周／月回看显示未完成承接建议，但不自动移动、不强制清零。

验收：从任意文档创建任务后 1 秒内出现在正确视图；从行动视图完成后原文同步；离线操作恢复网络后最终一致；刷新、跨标签页冲突和撤销均不产生重复任务；元中的任务默认不聚合。

### S9｜搜索、历史、导出与恢复

目标：完成长期工作的找回与数据所有权闭环。

交付：

- 统一搜索周期文档、具名文档、元和行动，结果标明来源并支持键盘跳转。
- 增加用户可见的版本历史与恢复预览；恢复前自动创建当前版本快照。
- 单文档与全量 Markdown 导出使用同一序列化器；清楚区分本人完整导出与共享公开导出。
- 提供本地草稿／冲突备份的恢复入口，而不是只留在 localStorage。

验收：搜索结果不泄露私密块；恢复任一历史版本后可再次撤销或从快照找回；全量导出后在空账号导入，文档数、标题、正文、任务状态和元内容语义一致；公开导出不包含任何私密文本。

### S10｜性能、无障碍与全矩阵 QA

目标：把“长期工作”转成发布指标。

交付：

- 浏览器矩阵：Chrome／Safari 当前稳定版；1440、1024、768、390；键盘、触控板和移动软键盘。
- 性能：编辑器长文输入、滚动、搜索、启动包和保存频率；按路由拆分非首屏模块。
- 无障碍：语义标题、焦点顺序、对话框焦点圈、状态播报、色彩对比和 reduced-motion。
- 故障演练：断网、超时、401、RLS 拒绝、存储失败、localStorage 配额、并发修改。

验收：5 万字文档连续输入无超过 100ms 的长任务，p95 输入处理低于 50ms；初始 JS gzip 不高于 400KB 或相较当前 476KB 至少下降 15%；关键路径 axe 严重／高危问题为 0；所有故障状态均有可恢复动作且不白屏。

### S11｜私有试用与发布准备

目标：只面向用户自己的隔离环境完成可回滚试用。

交付：

- `docs/releases.md`：版本、迁移、配置、已知限制、备份、恢复和回滚。
- 只记录错误类型、耗时和版本的最小可观测性；不采集文档正文、任务文本和私密块。
- 预发布数据备份；迁移 dry-run；真实账号的日／周／月、元、行动、搜索、导入导出、离线恢复验收。
- 上游许可、产品名称、域名和分发边界核查；当前仓库未发现独立 LICENSE，不能默认公开分发（`docs/baseline.md:77-79`）。

验收：连续 7 天个人真实使用无内容丢失；阻断级错误为 0；备份恢复演练成功；用户签署体验验收后才允许发布。推送、迁移与部署仍需分别获得明确授权。

### S12｜第二阶段：小团队增强

启动条件：S11 已稳定，且用户重新确认团队场景、成员角色和默认可见性。

候选顺序：文档级显式分享 → `@` 与行动的明确转换 → 负责人／反馈 → 块评论 → 实时协作。每一步先定义 owner、成员、访客能读写什么；隐藏入口不能代替 RLS（`AGENTS.md:18-19`）。

首版保留的现有协作只能做兼容回归，不作为 S12 已完成的证据。

## 8. 每个切片的固定流程

1. **Ready**：只选一个用户问题；写包含／不做／验收／数据影响／回滚的任务卡。
2. **实现前基线**：记录相关测试、浏览器状态、数据库 schema 和工作树；不混入无关重构。
3. **小步实现**：优先改现有模块和 `src/lib/` 领域边界；每个中间状态可运行。
4. **自动验证**：目标测试 → 全量 `npm test` → `npm run lint` → `npm run build` → `git diff --check`。
5. **浏览器验证**：按影响覆盖主路径、空／加载／错误、键盘、主题和宽度。
6. **数据验证**：若涉及数据，在隔离库验证保存、刷新、权限、失败恢复、迁移和回滚。
7. **代码审查**：安全／架构／体验问题修复后再做去冗余检查，随后重新跑回归。
8. **User Check**：向用户展示实际界面和限制；用户未验收则不标 Done。
9. **交付记录**：更新计划、契约、backlog 和 release note；说明已验证、未验证和下一步。

这一流程延续现有 `Idea → Ready → Doing → Review → User Check → Done`（`.omx/plans/development-workflow.md:30-63`）。

## 9. 测试体系

| 层级 | 重点 | 发布阻断条件 |
| --- | --- | --- |
| 单元 | Markdown 往返、任务 ID、日期、主题映射、索引重建 | 任一数据语义测试失败 |
| 组件 | DocEditor、Slash、导入对话框、导航、行动视图 | 焦点、Undo、IME 或错误恢复失败 |
| 集成 | docsApi、resilientDocs、doc_tasks、版本、RLS | 内容丢失、索引漂移或越权读取 |
| 浏览器 | 核心闭环、响应式、键盘、Safari／Chrome | 主路径不可完成或控制台运行错误 |
| 迁移 | 空库、旧库、回滚、内容哈希 | 数据数量／哈希变化无解释，或回滚失败 |
| 试用 | 7 天真实个人工作 | 阻断错误、内容丢失、无法恢复 |

每次测试报告必须把“自动通过”“浏览器通过”“数据库通过”“人工通过”分开，不用构建成功代替产品验收（`AGENTS.md:31-34`）。

## 10. 主要风险与缓解

| 风险 | 后果 | 缓解 |
| --- | --- | --- |
| 把 `doc_tag` 当永久文档模型 | 导航、标签、导入语义继续混乱 | S3 先定 `docs` 增量模型；S6 替换兼容层 |
| 任务成为第二份真源 | 正文与行动列表状态分裂 | taskItem + task_id 为真源，索引可重建 |
| 视觉重构破坏编辑器 | IME、选区、Undo 回归 | S1 先封板；S4/S5 每片跑编辑器浏览器矩阵 |
| 隔离环境误连原项目 | 污染真实数据或部署目标 | 不复用 `.env.example` 默认值；环境清单逐项核验 |
| 旧迁移与真实库漂移 | 部署失败或权限泄露 | 空库／旧库双演练；schema preflight；不改历史迁移 |
| 私密块从索引／历史泄露 | 严重隐私事故 | owner-only 历史、公开投影、跨账号负向测试 |
| 离线重放覆盖新版本 | 长期内容丢失 | 保留 `UNKNOWN_BASE`／版本前置条件（`src/lib/resilientDocs.js:56-73`） |
| 主题过多拖慢设计 | 细节不一致、难验收 | 先 4 套完整主题，通过后扩至 8–12 套 |
| 大包和长文卡顿 | 不适合长期工作 | 路由拆包、性能预算、5 万字真实浏览器门槛 |
| 当前磁盘不足 | 测试、浏览器和构建随机失败 | 持续警告并监控实际 `ENOSPC`；不再清理其他缓存，不擅自删除用户数据 |

## 11. 用户确认节点

以下节点必须由用户确认，不能由实现层替代：

1. 本主计划与首版明确不做项。
2. S2 的桌面信息架构和行动最小状态。
3. S3 的独立文档模型、元的可见性和增量迁移方案。
4. S4 的字体、4 套首发主题及逐背景固定印色。
5. 创建隔离 Supabase、执行任何 migration 或导入测试数据。
6. S11 的私有发布目标、域名、备份和上线时间。
7. 是否启动 S12 团队增强。

## 12. 总体验收标准

只有同时满足下列条件，才称为“观复个人可用版”，而不是 Demo：

- 核心闭环可在 10 分钟内独立完成，键盘全程可用。
- 编辑器契约全部通过，真实 macOS 中文输入无丢字／重字／跳光标。
- 日／周／月、具名文档、元、行动、搜索、历史、导入与导出均使用真实持久化。
- 文档、任务索引、公开投影和版本在刷新、离线、冲突及恢复后保持一致。
- 跨账号权限矩阵无私密内容泄露。
- 1440／1024／768／390 布局、明体／宋体和首发主题通过视觉验收。
- 全量测试、lint、构建、迁移演练和浏览器矩阵通过；无新增未解释 warning。
- 7 天个人试用无内容丢失，且已完成备份恢复演练。
- 用户明确批准发布；此前不得宣称产品完成或擅自部署。

## 13. 下一步

用户批准本方案后只启动 S0，不直接跨入数据迁移或 UI 大改。S0 完成后提交一份真实当前基线和 S1 编辑器剩余验收清单，再逐切片推进。
