# UI 风格探索 · 01

日期：2026-09-04。状态：第二轮探索中，未选定方案，未接入正式应用或数据库。

## 已确认的边界

保留现有记录、安排与跟进方式；优先改善编辑顺滑度和长期工作的视觉体验。用户希望简约、现代、优雅，少量中国／日本古典气息，探索类似明朝／宋体的特殊字形。

本次按用户要求先展示风格，不要求先完成整套 MVP 问卷。它是探索性原型，不表示其他功能或数据模型已经获批。

## 设计主张

- **视觉主张**：现代工作界面为骨架，宋／明朝风格标题、低彩度底色和克制留白提供东方气质；不使用仿旧纸纹、卷轴、手账横线或装饰山水。
- **内容结构**：轻量侧栏 → 日／周／月／收集箱与标签 → 连续编辑区。用同一份虚构工作内容比较风格，避免内容差异干扰判断。
- **交互主张**：点击文字直接编辑；工具按需展开；专注时收起侧栏。动效限于短促的选中态、勾选反馈和版面切换，尊重减少动态效果偏好。

## 三个初始方向

| 方向 | 字体与表面 | 取舍 |
| --- | --- | --- |
| A · 素白／明朝 | 中性偏暖白、青灰重点色；宋体标题与无衬线正文 | 工作属性最强，东方气息含蓄；作为初始展示，不代表用户选择 |
| B · 暖白／朱砂 | 浅米白、朱砂重点色；更舒展的宋体排版 | 文气更明显，需验证长期录入是否过于书卷化 |
| C · 墨夜／青灰 | 低彩度深灰、柔和浅色正文、青灰重点色 | 探索夜间工作氛围；仍需用户判断，并不宣称护眼效果 |

字体先以 Noto Serif SC 与系统无衬线字验证层级。宋体标题不等于真实明代刻本复刻；如果用户希望更强烈的古籍字形，下一轮再做具体字库比较及授权、字重、简体覆盖和体积核查。正式实现应考虑本地化字体资产和合理子集，避免编辑依赖外网字体加载。

## 本次样稿可体验的范围

- 切换三种配色／字体／间距组合，比较同一份内容。
- 切换正文宋体与无衬线体，标题保留宋体。
- 输入样例文字、勾选待办、追加待办、展开文字显示设置。
- 切换日／周／月／收集箱与工作／生活样例；每个视图的改动仅保存在当前页面内存。
- 收起侧栏进入专注布局；窄屏自动使用紧凑导航。
- 所有内容为虚构样例；明确显示“样稿 · 不会保存”，刷新会恢复默认。

没有实现：正式 Tiptap 接入、可靠自动保存、跨设备同步、真实通知、数据库权限、生产环境中文输入法与粘贴行为验收。不能用这个轻量样稿宣称正式编辑性能已经改善。

## 第二轮修正：不是“国风主题”，而是工作文档系统

第一版的问题已经明确：普通宋体点缀不够接近碑帖／古籍；仍出现源项目名称和通用导航图标；正文几乎由待办构成；三种样式彼此分散，没有形成统一设置；纸张材质被过早排除。

第二版据此采用以下设计主张：

- **视觉主张**：以低噪声现代工作空间承载古典排印；字体与传统色构成统一显示系统，不靠纸张模拟、山水、灯笼、祥云等装饰证明“中国风”。
- **内容结构**：无品牌工作空间 → 纯文字时间导航 → 一份连续工作文档；行动、过程记录、决策、资料和跟进共同构成内容。
- **交互主张**：直接编辑、按类型插入内容、显示设置即时预览；切换材质时不改变信息结构与功能位置。

### 产品设计哲学 v0.1

1. **器用为先**：每个视觉元素首先帮助工作；美学强化秩序、专注与记忆，不抢夺内容。
2. **古为今用**：取碑帖的骨力和活字的节奏，用现代交互承载；不做古装式界面。
3. **字成气质**：题名可用碑帖／行书，章节与正文用仿宋／明体，操作层保持易读；字体是信息层级，不是随机皮肤。
4. **文档为体，行动为用**：待办、笔记、决策、引用、附件、协作反馈都是同一工作文档的内容类型。
5. **无图标优先**：导航先用位置、文字、编号和状态线表达。只有在文字更慢且含义稳定时才设计图形；不直接套用通用图库制造风格混杂。
6. **色从材质**：每个方案由纸、墨、强调色和状态色组成；同一界面只出现一个主强调色。
7. **可久用**：正文对比、行长、行距和字重优先服务长时间读写；纯色表面保持安静、稳定。
8. **动以示意**：动效只解释状态、层级和位置变化；不用循环飘动、墨迹扩散等表演性效果。

### 显示设置模型

| 维度 | 第二版样稿 | 原则 |
| --- | --- | --- |
| 字体 | 明体、宋体、仿宋为主要字体；书法体仅用于题签／序号 | 一次选择决定整篇主要字形；操作文字保持现代无衬线 |
| 传统色 | 月白、竹青、天青、朱砂、缃叶、绀青、藕荷、秋香、茶褐、黛蓝、胭脂、松烟 | 色彩覆盖画布、侧栏、正文纸面与设置区，不再只是强调色 |
| 纸张 | 暂不设计 | 当前统一使用纯色表面；不再模拟宣纸、竹纸或洒金纹理 |
| 排版 | 紧凑、舒展 | 影响段间距和行距，不改变内容类型 |

字体样稿以 Noto Serif SC 作为默认明体长文，系统宋体／仿宋用于方向比较，Ma Shan Zheng 仅用于时间标识和章节序号。正式选型优先进一步试验 [朱雀仿宋](https://github.com/TrionesType/zhuque) 这类以历史活字为依据的正文方案，同时核查版本完整度、简体覆盖、文件体积与许可。

### 参考应用的抽象结论

- 根据一份 [素记公开评测](https://agirls.aotter.net/post/52812)，它强调纯文字、简练样式、多字体和信纸选择；采用“内容先于装饰”和统一显示设置，不复制其日期字样或具体页面。该参考发表于 2018 年，只作为设计线索，不视为产品当前状态。
- [西窗烛的 App Store 介绍](https://apps.apple.com/cn/app/%E8%A5%BF%E7%AA%97%E7%83%9B-%E5%93%81%E5%91%B3%E4%B8%AD%E5%9B%BD%E8%AF%97%E8%AF%8D%E4%B9%8B%E7%BE%8E/id912139104) 强调“古典文化，现代传承”，同时突出纯净排版、字体、书法练字和古风书笺；采用“现代交互承载传统文字”的方向，不把诗词阅读结构照搬到工作工具。
- 两者都是审美参照而非功能模板。本产品仍以高频工作文档和可靠编辑为中心。

### 第二版验证记录

- 已验证三种字形体系、六种传统色、三种纸张、两种排印密度的即时切换；设置摘要随选择更新，内容结构保持不变。

### 第三版修正与验证

- 颜色从“白色纸面 + 单一强调色”改为完整染色材质：画布、侧栏、正文纸面、设置区都属于所选色系；扩展到 12 套传统色。
- 默认正文改为明体，另提供宋体、仿宋方向；标题与正文采用同一主要字体，书法体只保留在题签／时间标识／序号。

### 第四轮决定：暂停纸张质感

- 用户明确认为当前模拟未达到要求；纸张质感从当前设计系统与近期实现范围移除。
- 第三版中生宣、竹纸和洒金的实验记录只保留为历史，不进入下一版样稿或正式产品规范。
- 后续使用覆盖整个工作空间的纯色表面，集中解决明体／宋体选型、传统色、排版层级和工作文档功能。

## 第五版方向：风入松与侘寂式减法

### 名称候选

首选设计代号为 **风入松**。它具备三字古典意象，风不可见、松只留下声响与姿态，适合表达轻、静、流动和未完成感；同时不把产品限定成日记或待办。

公开检索可确认“风入松”也是古琴曲、曲牌／词牌名称，并存在同名文化机构与书店。当前仅作为设计代号与候选名，不代表商标、应用商店、域名或公司名称已经可用；正式定名需另做分地域、分品类检索。

### 构建前设计主张

- **视觉主张**：一整面低饱和雾青纯色，明体细字、发丝线和不对称留白；东方感来自克制与间距，不来自装饰或纸张。
- **内容结构**：极轻侧栏承载名称和时间范围，主区只保留一份工作文档；显示设置默认收起，需要时覆盖出现。
- **交互主张**：文字直接编辑，行动可勾选，内容类型按需插入；导航、设置和状态变化短促而安静，不移动核心文档位置。

### 这一轮明确删除

- 删除纸张类型与全部纹理；不再模拟宣纸、竹纸或洒金。
- 删除永久右侧设置栏、章节数字、边框密集分区、强对比强调色和大字号书法展示。
- 删除装饰性农历、英文月份、拟古标签及重复状态说明。
- 保留明体／宋体作为主要字体，操作层维持现代无衬线；书法不再承担主视觉。

### 保留的功能骨架

- 时间范围、工作／生活上下文仍在，但使用纯文字与位置表达。
- 工作文档仍包含目标、行动、过程、决策与跟进，不退化为待办清单。
- 传统色仍可在显示设置中选择，但每套颜色降低饱和度和表面层级数量。

### 第五版验证记录

- 默认显示为纯色雾青、明体正文和收起的设置栏；没有纸张纹理、通用图标、章节数字或最后整理时间。
- 已验证明体／宋体切换、12 套低饱和色系、显示栏开合、时间导航、行动勾选、文字编辑，以及记录／行动／决定区块插入。
- 浏览器检查 1024px、736px、360px、320px；页面无横向滚动，320px 打开的显示栏仍完整落在界面内。隐藏设置栏位于画布外但不可见、不可操作，不计为可见元素溢出。
- 12 套色系的主要／次要文字相对内容、侧栏与设置表面的静态对比度最低为 4.54:1；浏览器 console 未记录 error／warning。
- 样稿脚本语法通过，不使用数据网络请求或持久化；正式应用源码、依赖和数据库未修改。

### 第六版信息减法

- 删除“风入松”下方的“工作文档”副标题，直接观察品牌默认字形与留白。
- 时间范围从今日／本周／本月／收集收敛为「日、周、月、元」；“元”的具体产品语义仍需在信息架构阶段定义。
- 协作区从“与 林舟／与 许宁”改为仅显示“林舟／许宁”。
- 显示设置删除“主要字体”和“色”标题；字体只保留明体、宋体两个直接选项。
- 色块直径由 15px 放大到 30px，名称保持 11px 注释层级；颜色承担主要识别，文字仅用于精确命名与无障碍理解。
- 浏览器验证 1024px 与 360px 布局；320px 打开显示设置时无可见交互元素横向溢出，console 无 error／warning。

## 第七版：观复桌面工作区

### 已确认

- 产品名改为 **观复**；“风入松”只保留为历史设计代号。
- 格言 **“万物并作，吾以观复”** 放在侧栏品牌名下方，长期可见但维持小字层级。
- 日／周／月从全局侧栏移到写作文档顶部，只切换当前文档的时间尺度。
- 左侧栏改为桌面工作区导航：工作区、最近、项目、共作。具体栏目与数据模型仍是交互样稿，不代表 MVP 功能已全部确认。

### 桌面尺度

- 桌面基准为 1440px：左栏 220px，文档模块最大宽度 940px，正文容器 780px；剩余空间用于呼吸与未来上下文，而不是拉长行宽。
- 在 1024px 宽度下仍保持独立侧栏、顶部路径、文档时间视图和完整正文；560px 以下才切换移动布局。
- 顶部第一层是项目／文档路径和操作；第二层是文档内部的日／周／月与工作标签；正文是第三层。

### 验证

- 已验证日／周／月选择会更新日期文字，侧栏各入口保持单选状态，显示设置、内容插入和文字编辑仍可用。
- 浏览器实测 1440px：可用宽度 1393px、侧栏 220px、文档 940px、正文 780px，无可见交互元素横向溢出。
- 360px 回退布局无横向溢出；console 无 error／warning。正式桌面应用仍需在实际 React 页面中验证窗口缩放、长文滚动和键盘焦点。

## 第八版：工具栏、斜杠与印章

### 工具栏

- 日／周／月从独立的文档次级栏合并到顶部工具栏，与工作、插入、显示处于同一横向层级。
- 桌面端保持左侧项目／文档路径、中央日／周／月、右侧工作／插入／显示；移动端在同一行显示缩小印章、日／周／月和操作。

### 斜杠功能组

- 任一可编辑文本位置输入 `/` 后显示 Markdown 功能组：标题一、标题二、待办、无序列表、有序列表、引用、代码块、分隔线、粗体。
- 当前交互样稿选择命令后把对应 Markdown 标记写入当前位置，用于验证菜单、定位、键盘触发和语法分组。
- 正式 Tiptap 实现应把命令转换为节点／Mark，并覆盖中文输入法 composition、上下键选择、Enter 执行、Esc 关闭、搜索过滤与撤销；不能停留在纯字符插入。
